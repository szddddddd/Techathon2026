# QQ 与网易 163 邮箱真实接入（只读）

选择 QQ 邮箱的标准 IMAP：无需注册 OAuth 应用，使用用户在 QQ 邮箱设置中生成的客户端授权码。支持 `@qq.com` 与 `@163.com`，每个平台一个独立连接。本版不启用 SMTP、不发送、不修改远端状态。桌面端另提供需单独授权的[邮箱 Agent](MAIL-AGENT.md)，使用校内模型分析所选邮件并生成本地草稿。

## 使用

1. 在对应邮箱网页版设置中开启 IMAP/SMTP 服务，生成客户端授权码。163 路径为“设置 → POP3/SMTP/IMAP → 新增授权密码”。具体设置名称可能随账号界面变化。
2. QQ 邮箱运行 `npm run mail:connect`，163 邮箱运行 `npm run mail:connect -- --mail-provider=netease`；也可以在本地窗口选择邮箱类型。在独立的本地窗口填写邮箱和授权码，不要在聊天中提供凭据。
3. 连接成功后点击“返回收件箱”。邮件与本地好友、演示消息一起展示，标记为“真实邮箱 · 只读”。
4. “消息 → 连接”可以手动收取、重新授权、断开并清除。回复请使用对应邮箱原应用。

普通网页与 Android 当前仍提供演示和操作指引，不收集真实邮箱凭据。无需为浏览器开放本地邮件 HTTP 接口。桌面端授权数据与浏览器账号/演示数据不自动互传。

## 数据与权限

- 固定 TLS `imap.qq.com:993` / `imap.163.com:993`，验证服务器证书，使用 IMAP EXAMINE 只读打开 INBOX。关闭连接不执行 CLOSE/EXPUNGE。
- 只读取最近七天、最新最多 200 封。每封邮件单独展示；本版不做跨邮件主题合并。
- 同步元数据，按 `INBOX + UIDVALIDITY + UID` 复用已取得正文。UIDVALIDITY 改变时重建当前窗口；消息和游标一起提交。每次刷新核对该时间范围，删除范围外及已不在收件箱的缓存条目。
- 只下载普通正文部分，上限 256 KiB，文本最多 60,000 字符。HTML 转为纯文本；不加载外部图片，不下载附件或附带的转发邮件。附件仅展示名称。
- 本地已读、置顶、待处理与回复草稿独立加密保存，不向服务器写标记。Agent 需要连接级 AI 处理／云端导出授权及逐次任务确认，不继承 IMAP 读取权限；不提供真实发送。
- 首次连接及后续同步均由用户触发，不启动后台轮询。失败保留上次成功缓存，可手动重试；登录失败显示重新授权。最长单次同步 90 秒，慢网络可重试，失败批次不提交。
- QQ 数据沿用 Electron userData 的 `inbox-mail-v1.enc`，163 数据使用独立的 `inbox-mail-163-v1.enc`，与 IndexedDB 演示库分离。Windows Electron safeStorage 包装随机密钥，AES-256-GCM 加密授权码、账号、正文、状态和最小审计。新增 163 使用独立的 GCM 附加认证数据，防止两个平台的密文互换。文件原子替换；加密不可用时拒绝保存，不降级为明文。
- 主场景与 Agent 不接收授权码。仅固定本地凭据窗口可提交，IPC 同时校验窗口、主 frame 和文件路径；禁止凭据窗口导航、弹出窗口与页面联网。主场景通过固定 IPC 查询、收取、设置本地状态／草稿／AI 权限，以及发起或取消受控 Agent 任务。
- 断开先使进行中的同步失效，再删除本机加密文件并清空内存投影。仍需用户另到对应邮箱撤销授权码。授权码自身可能允许读写；应用只读不等于平台颁发只读令牌。系统保护不防同一用户权限下的恶意程序。

## 验证边界

- `npm run test:mail`：模拟 IMAP 客户端验证范围、只读、正文/附件选择、复用与去重、游标失效、失败原子性、撤销竞态、密文校验和演示/Agent 隔离。
- `node scripts/test-mail-browser.mjs`：使用合成邮箱投影验证阅读、收取、清除、来源标记、移动端指引；截图在 `.test-results/mail-*.png`。
- `node scripts/test-mail-desktop.mjs`：在独立 Electron 配置中检查真实 safeStorage、独立凭据页面、CSP 与 IPC 拒绝路径。
- 上述自动测试不代表已登录用户邮箱。只有本地连接窗口返回成功，才表示该账号的 IMAP 认证、INBOX 读取和本机保存已实测。SMTP、OAuth、其他邮箱、移动端真实接入均未验证/未启用。
- 本次另验证了 QQ IMAP 的真实 TLS 连接及服务器证书，未发送账号凭据。构建、Inbox 单元/浏览器回归及社交存储测试通过。额外的旧桌宠桥接脚本在初始可见性断言处超时：其模拟初始值为隐藏，却等待打开；本次未修改该脚本或桌宠行为，不将该项计为通过。

依据：[腾讯官方客户端邮箱集成说明](https://main.qcloudimg.com/raw/document/product/pdf/1270_46586_cn.pdf)、[ImapFlow 官方接口](https://imapflow.com/docs/api/imapflow-client/)、[Electron safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage)。腾讯资料证明协议与授权码路径，当前账号开通条件仍以实际设置及连接结果为准。
